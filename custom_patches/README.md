# 自定义内核补丁

将标准 unified diff 格式的补丁文件放在此目录。构建时需要在工作流输入中启用 `apply_custom_patches`；该选项默认关闭。

## 文件命名

文件名必须采用以下格式：

```text
顺序-最低内核版本-最高内核版本-名字.patch
```

版本字段使用完整的 `主版本.次版本.补丁版本` 格式。例如：

```text
0001-5.10.0-5.10.271-cve-2026-98432-ipv4-rcu-free.patch
0002-5.10.0-5.10.261-cve-2026-64560-posix-cpu-timers.patch
0003-5.10.0-5.10.260-cve-2026-43499-rtmutex.patch
0004-5.15.0-5.15.223-cve-2026-98260-posix-timer-exec.patch
```

### 顺序字段

- 顺序字段可以是任意长度的十进制数字，不限制为四位。
- 可以使用 `1`、`0001`、`00001` 等写法；前导零不影响顺序值。
- 脚本按顺序字段的数值从小到大应用补丁，例如 `0002` 排在 `00010` 之前。
- 数值相同的补丁可以使用相同顺序号，但它们的内核版本范围不能重叠。
- 相同顺序号的版本范围发生重叠时，脚本会报错并终止当前构建。

### 内核版本范围

- 最低版本和最高版本都包含在适用范围内，即 `minVer <= currentVer <= maxVer`。
- 不限制内核版本时，最低版本和最高版本必须同时填写 `all`，例如 `0004-all-all-custom-fix.patch`。
- 两个版本字段必须同时使用具体版本，或者同时使用 `all`。
- 当前内核版本从本次构建的 `common/Makefile` 中读取 `VERSION`、`PATCHLEVEL` 和 `SUBLEVEL`。
- 不在版本范围内的补丁会记录跳过原因，不执行 `git apply`。

## 按序号选择补丁

工作流提供两个输入项，用于按文件名中的顺序号选择自定义补丁：

- `custom_patch_selection`：填写序号、逗号分隔的多个序号，或连字符表示的连续范围。
- `apply_selected_patches`：为 true 时只应用输入框选中的序号；为 false 时跳过选中的序号，并应用其他适用补丁。

输入格式示例：

```text
all
1,02
001,14,51-400,1919-810
```

`all` 表示选中全部补丁。序号和范围端点都按十进制数值比较，范围包含起点和终点。前导零不影响匹配，例如文件名中的 `0003` 可由输入 `3` 选中。

默认值为 `custom_patch_selection=all`、`apply_selected_patches=true`，即应用全部适用补丁。

序号筛选需要同时启用 `apply_custom_patches`。未启用该选项时，补丁脚本不会执行。

## 自定义补丁失败处理

工作流提供独立的 `skip_failed_custom_patches` 开关，默认关闭。

- 关闭时，适用补丁在解析、预检查或实际应用阶段失败，当前内核构建立即终止。
- 开启时，失败补丁会被跳过，脚本继续处理后续补丁，内核构建继续执行。
- 补丁文件名、版本范围和路径安全检查属于配置检查；这些检查失败时始终终止构建。
- 版本范围或序号筛选不匹配的补丁会正常跳过，不计入应用失败数量。

失败补丁会单独生成 Actions 日志分组，输出以下信息：

- 补丁路径、文件 SHA256、文件大小、当前内核版本和适用范围。
- 失败阶段、执行命令和退出码。
- 补丁涉及的源码文件。
- `git apply` 的完整错误输出。
- 补丁文件开头最多 80 行，便于确认补丁来源和 hunk 内容。
- 源码工作区的 `git status` 和涉及文件的当前差异。
- 是否跳过该补丁并继续后续处理。

如果实际执行 `git apply` 失败，脚本会恢复该补丁涉及文件在应用前的内容，再继续处理后续补丁。失败数量和失败补丁文件名会在脚本结束时汇总。

该开关只影响自定义补丁脚本的失败处理，不会忽略其他内核构建步骤中的错误。

## 一个补丁修改多个文件

同一个 `.patch` 文件可以包含多个 `diff --git` 文件段。把同一项修复涉及的所有文件变更放进一个补丁文件即可。

例如，一项修复同时修改：

- `net/ipv4/af_inet.c`
- `net/ipv4/tcp_ipv4.c`

应将这两个文件的 diff 放进同一个补丁文件。脚本会先对整个补丁文件执行一次 `git apply --check`，通过后再执行一次 `git apply`，将其中多个文件作为同一个补丁单元处理。

## Actions 日志

每个补丁会单独使用一个 Actions 日志分组，并打印：

- 补丁文件名、顺序号、当前内核版本和适用范围。
- 补丁涉及的文件路径。
- 补丁检查结果。
- 应用前后源代码的 unified diff，包含修改行和定位上下文。
- 成功应用补丁时，在补丁日志中打印 `✔` 标记。
- 每个补丁日志分组结束后打印独立分隔线，方便逐个审计。
- 版本范围或序号筛选不匹配的补丁会打印跳过原因。

补丁文件开头的说明文字不会混入成功应用补丁的源代码差异日志。

该选项独立于 Clean Build，可用于只构建原生内核并手动集成安全补丁。
